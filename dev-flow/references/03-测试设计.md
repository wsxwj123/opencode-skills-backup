# 03 测试设计（只有标准档走这里；轻档、中档用轻档.md 里的限量测试代理）

目标：在写第一行实现代码之前，由独立代理站在用户角度写好验收测试并锁定。写测试的不许看实现，否则测试会迁就实现。

## Step 1：测试设计代理（独立子代理）

输入只有 `.devflow/BRIEF.md` + `.devflow/INTERFACE.md` + 预算块（测试设计），不给 PLAN.md。

Prompt 照抄："只依据我给你的这两个文件（BRIEF.md、INTERFACE.md）设计测试；除这两个文件外，不得查看 `.devflow/` 下任何其他产物，不得查看项目源码和 git 历史。站在真实用户的角度设计测试。"

要求覆盖（缺哪类要说明为什么不适用）：

1. 正常路径：BRIEF 里每条"输入X→得到Y"的主路径。
2. 边界：0、1、空、负、极大极小、临界值、单元素、超长、Unicode。
3. 错误路径（最易漏）：乱输入、空输入、缺参、类型错、重复操作、文件缺失、断网、越权、依赖不可用，必须被正确拒绝，每种断言具体的失败行为（确切的退出码、异常类型、报错文案）。
4. 反向用例：不该发生的事断言它没发生（不该写库的没写、不该删的文件还在）。
5. 幂等、并发（若适用）：重复调用、并发调用不产生脏数据。
6. 需求没明说但按常理必须正确的行为（中文文件名、路径带空格），按 BRIEF 的平台范围顾兼容性。

每个测试只测一件事，命名说清场景；断言具体，不只断言非空、不报错；测试间无依赖，能任意顺序跑；不引入没必要的框架和 fixture。交付时明说覆盖了什么、没覆盖什么。

规模：默认总数不超过 30 条，超出要在 TEST-PLAN 写明理由；默认只派 1 个代理，多个互不相关的子系统才分组（一个项目 4 组代理写了 717 条，冒出 46 处接口不清）。

## Step 2：产出（按项目类型分叉）

| 类型 | tests/acceptance/ 里放什么 |
|---|---|
| 代码/脚本 | 可执行测试（pytest / node test），只通过对外接口调用（CLI、公开函数），不 import 内部模块 |
| 网页/前端 | **`@playwright/test` 的 spec 测试文件**（npm 标准测试框架，带断言/报告，`npx playwright test` 可复跑、可进 CI）走真实用户流程：打开页面→操作→断言看到的结果。注意：playwright **MCP** 和 agent-browser 是交互式驱动工具，产不出可提交复跑的测试文件，**不能当验收测试产物**（它们的定位是 04 开发期探路调试） |
| skill/prompt | 测试 prompt 清单 + 每条的产出评分标准（什么样算合格），供 05 裁判盲测 |

同时产出 `.devflow/TEST-PLAN.md`（给用户看的清单）：每条一行，场景 / 怎么操作 / 预期看到什么。

## Step 3：守卫检查（主会话执行）

先跑 `pytest --collect-only tests/acceptance`（或等价命令）确认用例都能被收集，收集不了的打回；从零开始的项目可以按 INTERFACE 加接口桩（只有签名，函数体 `raise NotImplementedError`）。再检查测试内容：出现 INTERFACE.md 之外的实现细节（内部函数名、私有模块、数据库表名）即打回 Step 1，新开代理重写，打回意见只说"第 X 条出现了 INTERFACE 之外的细节"，不复述内部名。

## Step 4 ⏸ 卡点2：清单锁定

把 TEST-PLAN.md 给用户过目：一共多少条、覆盖哪些方向、哪几条是替用户想到的。用户可增删。确认后锁定：

```bash
git add tests/acceptance .devflow/TEST-PLAN.md <接口桩文件> && git commit -m "test: 验收测试锁定"
git rev-parse HEAD > .devflow/LOCK
shasum -a 256 .devflow/BRIEF.md .devflow/INTERFACE.md .devflow/TEST-PLAN.md > .devflow/LOCK.sha   # 判据文件指纹：公开仓清洗后这些文件不再被 git 跟踪，05 靠它核对
echo "标准档锁定 $(cat .devflow/LOCK)" >> PROJECT.md
git add .devflow/LOCK .devflow/LOCK.sha PROJECT.md && git commit -m "chore: 记录验收测试锁定 hash"   # 公开仓已 ignore 这些路径时 git add 会报错，跳过这次提交，文件留本地即可
```

锁的真值从 git 推：`git log --grep='^test: 验收测试锁定' --format=%H -1`，LOCK 文件和账本是副本，05 Step 1 三者比对。此后开发代理对 `tests/acceptance/` 只读。

锁定后发现测试有夹具或时序问题：新派测试设计代理（只给 BRIEF + INTERFACE + 失败现象）修，核查 diff 含夹具和数据文件，改完重新锁定。不许开发代理改，不许续用原测试代理（改夹具是测试迁就实现的后门）。

## 修 bug

默认走轻档.md。只有标准档的 bug（动数据结构、删除路径、批量改写）才到这里：核心产物是复现测试，修前必须失败、修后必须通过，加 1–2 条相邻回归用例，锁定后进 04。

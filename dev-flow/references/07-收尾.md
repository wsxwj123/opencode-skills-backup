# 07 收尾

目标：用户亲手确认真实效果，同步知识，清理现场。发布了不等于做完了。

## Step 0：部署实测（主会话执行，交给用户前先自己跑一遍）

开发机上能跑不等于装到目标环境能用，验收和单测测不出部署环节的坑。交卡点 5 前主会话按真实部署路径过一遍：

- 照 README 从零跑一遍安装或部署，不复用开发时的现成状态。
- 能自动化的自己驱动一遍：装完核验底层逻辑能独立跑通；有常驻进程或扩展的，确认在跑的是本次新构建不是旧实例；产物路径、运行时 PATH、依赖跟开发机一致。
- 过一遍常见部署坑：旧实例没换、安装脚本漏拷文件或路径写死、运行时解释器与开发机不同、产物权限、签名、隔离属性拦截。
- 必须手动点 GUI 的部分（系统弹窗）主会话驱动不了，交用户时列出具体要看的失败迹象，不只说"你试试"。

## Step 1 ⏸ 卡点5：用户实测（按项目类型给可操作的验收方式）

| 类型 | 给用户什么 |
|---|---|
| 网页（已部署） | 线上地址，请用户亲自打开点一遍核心流程 |
| 程序/软件/脚本 | 具体运行命令（从安装到跑起来，照 README），请用户**在自己机器上实际跑一遍**；有右键/服务/GUI 等**真实集成入口的，让用户驱动那个入口，不只跑核心命令** |
| skill | 请用户开新会话真实调用一次，看产出是否符合预期 |

用户说不行：记录问题，回 [轻档.md](轻档.md) 走一轮，根因在架构上的回 02 中档走法。用户确认没问题，继续。

## Step 2：知识同步与复盘

1. 调用 `neat-freak` 技能，同步代码、文档（README、CLAUDE.md）、记忆三端一致。
2. 复盘写进项目根 `LEARNINGS.md`：踩了什么坑、什么做法值得沿用（项目专属写本地，跨项目通用写 `~/.learnings/`）。
3. 账本瘦身：PROJECT.md 只留当前状态、下一步、关键决定、待办、未关闭 Bug、最新一条阶段进度，旧进度和各代理记账移到 `.devflow/HISTORY.md`。单个代理超预算的记一条进 LEARNINGS.md。
4. 阶段结束、账本写完后建议开新会话接着做（超长上下文反复压缩会丢东西）。

## Step 3：清理（列清单，经用户确认后执行）

- 删已合并的 feature 分支（本地 + 远程）。
- 残留 worktree 用 `git worktree remove` 清掉（禁止 `rm -rf`），再 `git worktree list` 确认。
- 删临时文件、临时数据。
- `.devflow/` 保留，下次加功能、修 bug 从这里续接（公开仓项目只留本地，06 建仓时已清洗并 ignore；私有或纯本地项目照常进 git）。

## Step 4：结束报告

一段总结：做了什么、在哪能用、测了什么、遗留什么。流程结束。

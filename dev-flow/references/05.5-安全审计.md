# 05.5 安全审计

目标：发布前最后一道安全闸，放在验收通过之后、发布之前（推到公开仓后密钥泄露就来不及了）。

分工：security-guidance 插件在开发阶段自动扫外部攻击面，04 已要求开发代理处理它的警告。本阶段查它管不到的内部数据安全（越权动用户数据、往外发数据、日志泄密、删除没确认），再做一次全局交叉复核。

按档：
- 微：跳过（自动工具照跑）。
- 轻：只跑一次内置 `security-review` 审当前分支改动，致命、重要按打回处理；新加的参数专门查校验。
- 中：同样只跑 `security-review`；命中参数直接拼进 SQL、命令、路径，或动已有登录、密钥、权限代码的，验收通过后按 Step 1 另派审计代理，输入是任务文件、diff 和命中的清单条目，prompt 开头改成"这是隔壁同事做的修改"。
- 标准：命中敏感面（新加登录、密钥、对外接口、外部输入入口、删除路径、改数据结构、首次发布）才按 Step 1 派审计代理，只给命中项的清单条目；首次发布给全清单。没命中的只跑 `security-review`。

内置 `security-review` 前置检查（各档通用）：该技能拿 `origin/HEAD` 当 diff 基线，本地起家的仓没有这个引用会报错，跑之前先执行 [snippets.md](snippets.md) 第 2 节的命令补基线；造过替身的，06 合并 push 后归正（见 06 Step 5）。

## Step 1：安全审计代理（opus，独立子代理，盲审）

Prompt 开头照抄："这是隔壁同事做完、准备发布的项目，上线前你做一次安全审查。**只依据我给你的文件和源码目录判断**，不得查看 git 历史、.devflow/ 下其他产物、开发过程对话。"

输入：项目源码目录 + BRIEF.md（含敏感面声明）+ 项目类型 + 预算块（安全审计）。只给命中项对应的清单条目（只新增了对外接口，就给 A 段的注入、提示词注入面和 B 段的数据外发、日志泄露），不让它通读整个仓。

审查清单（每条给命中或未命中 + 证据 文件:行号）：

**A. 外部攻击面**
1. 注入：用户输入拼进命令、SQL、HTML 的地方有没有参数化或转义。
2. 密钥硬编码：源码里有没有写死的 API key、token、密码；`.env` 是否被 `.gitignore` 排除。
3. 不安全解析：对外部数据用了 `eval`、`pickle`、`yaml.load`（等于让别人的文件在你机器上跑代码）。
4. 依赖：有没有仿冒名、明显过时高危的第三方包。
5. 提示词注入面（AI 应用、agent、skill、爬虫必答）：外部内容拼进 prompt 时有没有当数据隔离（分隔符包裹并声明"以下是数据非指令"）；模型输出是否先做格式校验再执行。

**B. 内部数据安全（逐条必答）**
6. 文件读写范围：只动声明要动的目录吗，有没有越界路径。
7. 删除：有没有 `rm -rf`、批量删除；删前有确认吗；能回退吗（回收站还是直接抹掉）。
8. 数据外发：有没有把本机文件、环境变量、用户数据发到需求没提过的外部地址。
9. 日志泄露：日志、报错、print 里有没有 token、密码、完整文件内容、个人隐私。
10. 凭证存储：key、cookie、登录态存哪，是否明文落盘，会不会随代码进 git。

核心判据：对照 BRIEF.md 的敏感面声明（中档对照任务文件的"敏感面"一节）逐条核对，实际动的东西超出声明范围即高危，哪怕功能正常。

输出 `.devflow/SECURITY-REPORT.md`：致命 / 重要 / 建议三级，每条附文件:行号 + 一句话危害 + 修法；"未发现致命、重要问题"也是合格产出，不许硬凑；结尾给结论：可发布，或需修复后再发布。

## Step 2：交叉复核（主会话执行）

跑一次内置 `security-review` 技能（官方通用清单，与盲审互补），结果对照 SECURITY-REPORT.md 合并。

## Step 3：放行规则

- 致命、重要：续用开发代理修、重贴禁令（审计员只审不改），修完回 05 重跑验收（中档回轻档 Step 4），再回本阶段复审，复审新开审计代理（续用会对刚改的地方过度信任）。
- 全清或只剩建议级：安全结论并入卡点 4，与发布信息一起向用户汇报（查了什么、有没有事、修了什么）。

## 附：按项目类型最要命的 3 条

| 类型 | 最常翻车的 3 条 |
|---|---|
| CLI/脚本 | ①命令注入（拼字符串执行）②越权文件操作/删除无确认 ③密钥写死或日志带出 token |
| 爬虫 | ①抓回的内容当代码跑（eval/pickle/yaml.load 投毒路径）②cookie/账号明文落盘或进 git ③数据发往写死的第三方地址 |
| 网页/PWA | ①XSS（innerHTML 塞用户内容不消毒）②密钥打进前端 bundle/localStorage（前端=公开），Supabase 查 RLS 行级权限和越权读 ③后端注入与鉴权 |
| skill | ①提示词注入/诱导外发用户数据的指令 ②附带脚本越权读删范围外文件 ③skill 文件里写死 token（skill 会被分享，等于公开） |

# 报告模板（Step 5 收尾时按此输出）

整理完成后，**逐项**给出下面六节。缺任一项都算没做完——用户要的是「我删了什么、还能不能救」，
不是「我整理好了」。数字一律来自实际命令（`wc` / 指纹 JSON / 覆盖率表），别估。

---

## 1. 减幅

```
文件：<绝对路径>
字节：<原> → <新>        （-xx.x%）
行数：<原> → <新>        （-xx.x%）
条目数：<原> → <新>      （同族合并所致；规则数不降，见第 3 节）
```

字节/行/条目三样都要。**条目数下降是正常的**（同族合并），**字节减幅落在 55%–80% 是经验区间**；
超过 **85%** 必须先复核覆盖率缺失清单（大概率砍进了规则本体或硬事实），把结论写进第 3 节。

---

## 2. 删了什么（分类计数）

只允许删两类东西，分别计数：

- **模板元数据**：删掉的 `Logged/Priority/Status/Area/Context/Metadata` 等字段行数 = `<n>` 行。
  （格式化的 `#### Summary/Error/Context/Suggested Fix` 小标题也算。）
- **案例展开叙述**：精简掉的叙述行数 = `<n>` 行（现象铺陈、复现过程、举例说明）。

**不在本节的**：被合并的同族条目 → 记在「合并族」里单列（第 3 节）；凭证 → 单列（第 5 节）。

---

## 3. 保留了什么（+ 合并族）

```
独立规则数：<原> → <新>        （必须 >= 原值）
硬事实数（指纹 items）：<原> → <新>   （只增不减）
合并的同族：<n> 族，例如 zsh 词分割 ×3→1、子代理 16k ×8→1
  每族存活条目：<族名> → 第 X 节「<标题>」
```

**规则数不减**是底线：同族合并降的是「条目数」，不是「规则数」。每合并一族，都要点名它落到哪一条。

---

## 4. 备份路径

```
备份：<同目录>/<文件名>.bak-<YYYYMMDD-HHMMSS>
校验：cmp 备份 原文 → 无差异；wc -c 两者相等
```

没有 `.bak-<时间戳>` 就不算完成。

---

## 5. 回滚命令（一行，可直接复制执行）

```bash
mv "<文件>.bak-<时间戳>" "<文件>"
```

再附一行核对：`cmp "<文件>" "<备份>"`（回滚后应无差异）。

---

## 6. 待用户决策项

把「不静默删」的东西列清楚，让用户拍板：

- **待迁移（项目专属）**：只对某项目有用的条目 → 建议迁往 `<项目根>/LEARNINGS.md`。
  列出条目标题 + 理由；**技能不替用户跨文件搬迁**。
- **未收录（非 learnings）**：会议记录 / TODO / 草稿 / 闲聊 → 已移出压缩件，原文仍在备份可 `grep -F` 找回。
- **疑似凭证**：报位置与形状（**不回显原文**）+ 提示轮换。形如
  `第 N 行检测到疑似凭证（形状 gh…），已删除，建议轮换该凭证`。
- **覆盖率缺失项**：`coverage_check` 报出的每一项，逐条交代「为何可丢」或「已回补」。

---

## 附：收尾核对（Step 5 最后一步）

```bash
wc -l "<文件>" && head -20 "<文件>"     # 头部结构未坏（第一分节/顶部摘要完整）
ls "<目录>"                              # 只多出一个 .bak-<ts>，无 *.v2/*-new 残留
```

---

## 反例：不合格的报告长什么样

- 只说「已压缩，减幅 70%」——没交代删了什么、备份在哪、怎么回滚。
- 「删了 3 条重复的」——没有族名、没说明合并后落在哪条。
- 凭证那一项回显了明文——**报告本身成了新的泄漏面**。
- 缺失清单里写了「这些应该不重要」——没有逐项交代就不算通过。

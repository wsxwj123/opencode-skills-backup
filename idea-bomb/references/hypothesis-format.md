# 摘要式假说：四要素怎么写

第二段的产物。一个种子展开成这样一份东西，才算成型的课题假说，才允许进库。

四要素缺一不可：研究背景、gap、研究思路与设计、创新点。四段合起来控制在一屏内，不是标书，也不是实验方案。

## 四要素

### ① 研究背景 `background`

这个问题现在是什么局面。一到三句，落到具体的现象和已有做法上，不要"随着……的发展"这种开场。

写对的样子：

> 瘤内活菌治疗的疗效批次间波动很大，现有解释集中在菌株活性和瘤内乏氧程度，没人系统看过给药时刻。

写错的样子：

> 近年来，肿瘤微环境调控已成为研究热点，工程菌治疗展现出巨大潜力。

差别在于：前者能让人接着问"那给药时刻怎么了"，后者接不下去。

### ② gap `gap`

前人漏掉的那一块，必须是能被一句话点名的空白，不是"研究还不够深入"。

好的 gap 通常长这样：某个被默认成立的前提，其实从没被直接检验过；或者两条各自成熟的线，没人把它们接起来过。

> 固有免疫细胞丰度有昼夜节律，但活菌治疗的全部剂量学研究都默认给药时刻无关紧要，这个假设从没被直接检验过。

自查一句：你的 gap 换成"前人没做过 X"之后，X 是一个具体动作吗？是就合格，是"研究得不够"就不合格。

### ③ 研究思路与设计 `design`

怎么验。写到大概的实验内容为止：用什么体系、比什么、看什么读出。

**不要写成详细实验方案**。不列分组表、不列时间点、不写剂量和统计方法。那是用户选定方向之后另议的事。

> 小鼠在两个相位点给同批工程菌，比较瘤内定植量、菌清除速率与荷瘤生长曲线，再用节律敲除鼠验证这个差异确实依赖宿主节律。

两三句讲清"怎么验"就停。真要展开详细方案，等用户点名要。

### ④ 创新点 `innovation`

新在哪，一句话。要能经得起"那又怎样"的追问——说清楚它带来什么别人拿不到的东西。

> 把时间生物学的相位变量引入活菌治疗剂量学，给出一个零成本就能提升疗效的调度维度。

别写"首次提出""填补空白"。查新结果写在 `closest_work` 和 `diff` 里，创新点这一栏讲的是价值，不是抢注。

## 证伪点 `falsification`

这一条最容易写成敷衍，也最见功力。它不是"可行性风险"，是"什么结果出来就说明我错了"。

要落到结构上，两步：

1. **点名承重变量。** 你的假设真正压在哪个因素身上？不是"这个机制"，是那一个具体的变量。
2. **配一个非同义反复的阴性对照。** 把承重变量拿掉，下游指标就该回落到基线。

> 承重变量是给药时刻的免疫细胞丰度差。若在节律敲除鼠里两个相位点的定植量差异消失，则本假设被证伪。

反例（同义反复，不管结果怎样都证伪不了什么）：

> 若工程菌无法在肿瘤定植，则本方案失败。

这句话说的是实验没做成，不是假设不成立。换个说法其实跟假设本身等价的对照，一律不算证伪点。

自查：你的证伪点里，那个"拿掉某某"的操作，是不是真能把假设的承重部分单独拿掉？拿掉之后如果指标没回落，你会不会真的承认自己错了？两个都是"是"才算过关。

## 查新证据

`novelty_queries` 填你实际跑过的检索式。别编。脚本查不出真假，但引一条不存在的文献是红线。

跨界迁移（`method=transfer`）必须给至少两条：一条搜目标领域，一条用源领域的原名再搜一遍。撞车最可能发生在源领域那头——那边早做过、只是换了套说法，只搜目标领域根本看不见。

`closest_work` 写最接近的那篇真实结果。确实没搜到就如实写"检索未见直接先例"，这是合法结论，此时 `diff` 可以留空。写了具体工作就必须写清差异点，不许用"—"或"无"顶替。

## 提交用的 JSON 形状

```json
{
  "idea": "一句话说清这个课题是什么（≥30 字）",
  "hypothesis": {
    "background": "……", "gap": "……", "design": "……", "innovation": "……"
  },
  "feasibility_layers": {
    "机制": "外域机制搬过来在本领域讲不讲得通",
    "体系实现": "在用户的体系里能不能真做出来，关卡看 profile",
    "三年立项": "三年内的条件够不够"
  },
  "falsification": "承重变量 + 非同义反复的阴性对照",
  "novelty_queries": ["目标领域检索式", "源领域原名检索式"],
  "closest_work": "PMID 38123456（……）",
  "diff": "和最接近的那篇差在哪（≥10 字；无先例时可留空）",
  "novelty": "中-高",
  "feasibility": "高",
  "quadrant": "甜区（创新中-高×可行高）",
  "source_domain": "时间生物学",
  "source_mechanism": "免疫细胞丰度的昼夜相位",
  "platform": "工程化细菌",
  "disease": "实体瘤",
  "method": "transfer",
  "status": "untried",
  "user_verdict": "采纳"
}
```

`feasibility_layers` 的键名随便起，只要有三层、每层 ≥10 字。`source_domain` / `source_mechanism` 是跨界迁移专用的，组合重组和换角度可以不写。`schema`、`date`、`committed_at`、`seed_id`、`archived` 由脚本自己填，写了也会被覆盖。

交给用户看的时候按 SKILL.md《交付时说人话》那一节讲，不要把这份 JSON 原样甩出去。

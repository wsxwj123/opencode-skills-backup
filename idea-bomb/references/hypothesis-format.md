# 摘要式假说规范

第二段的产物形态。种子展开为本格式后方可入库。

## 文体基准

参照系为国家自然科学基金申请书的立项依据。以下为完整写作规范。

### 段落式叙事

全文以完整段落展开，**禁止使用项目符号或编号列表展开论述**。每段 150 至 400 字，段内含主题句、展开句、过渡句，段落间以逻辑衔接。四要素可分节，但每节内部必须为段落而非条目。

### 叙事线

按以下逻辑线组织：宏观背景（领域问题）→ 聚焦具体对象 → 国内外研究现状（已有结论与依据）→ 关键空白或矛盾 → 本方向的切入点 → 凝练科学问题。

### 引用

论断须附编号引用（`[1]`、`[2,3]`），禁用"大量研究表明"等模糊表述，须给出具体作者与年份。文末列参考文献，编号对应正文，每条含作者、期刊、年份、PMID 或 DOI。仅列真实检索所得文献。

### 术语解释

概念解释须融入叙事句中，**禁止单列加粗条目清单**。用户专业范围以 `profile.md` 为准，超出范围的概念首次出现时须在同一句内阐明。

### 反 AI 禁令

禁止句式：不是……而是……；不仅……而且……；至关重要；不可或缺；具有重要的理论意义和实践价值；蓬勃发展；深入探讨；系统研究；全面分析。

修辞禁令：排比、反问、设问、夸张（革命性的、颠覆性的）。

标点禁令：装饰性破折号；术语引号；解释性冒号。

其他：不回避系动词（用"是"而非"充当""具备"）；同一段内概念称谓须统一。

### 节奏

长短句交替，避免连续三句长度相近。连续两段不以相同结构开头。

### 自检

产出提交前逐句检查：（1）禁用词和禁用句式是否出现；（2）论断是否附引用；（3）段落式叙事是否完整（无条目列表）。长句属软提醒，机制类严密长句可保留。

## 四要素内容要求

### ① 研究背景 `background`

领域局面与研究现状。须含具体研究者、具体结论与具体引用。禁止口语叙述或条目切块。

### ② gap `gap`

前人未覆盖的关键空白，可为理论空白亦可为实践中的未解问题，须可用一句话准确概括。承接背景段末句。自检标准：改写为"既往研究未开展 X"时，X 须为一项具体的研究动作。

### ③ 研究思路与设计 `design`

验证路径。写至大致实验内容即止——使用何种体系、比较对象、读出指标，两三句打住。**禁止列分组表、时间点、剂量或统计方法。**

### ④ 创新点 `innovation`

一句话阐明新颖之处，须经得起"意义何在"的追问。禁用"首次提出""填补空白"。查新结果写入 `closest_work` 与 `diff` 字段，本栏陈述价值。

## 证伪点 `falsification`

须回答"什么结果出现即说明假设不成立"，而非"什么风险可能导致实验失败"。

结构分两步：（1）指明承重变量——假设真正依赖的那一个具体因素；（2）配置非同义反复的阴性对照——移除承重变量后下游指标应回落基线。

自检：移除操作能否单独去除假设的承重部分？指标未回落时是否足以否定假设？两项均为"是"方合格。与假设本身等价的表述（如"若菌不定植则失败"）不构成证伪点。

## 查新证据

`novelty_queries` 须填写实际执行过的检索式。跨界迁移（`method=transfer`）至少两条：一条搜目标领域，一条用源领域原名检索。

`closest_work` 填最接近的真实检索结果。未检索到先例时写"检索未见直接先例"，此时 `diff` 可留空。填写了具体工作则 `diff` 必填且 ≥10 字。禁止编造文献。

## 提交 JSON 结构

```json
{
  "idea": "一句话说清这个课题是什么（≥30 字）",
  "hypothesis": {
    "background": "……", "gap": "……", "design": "……", "innovation": "……"
  },
  "feasibility_layers": {
    "机制": "外域机制搬过来在本领域讲不讲得通",
    "体系实现": "在用户的体系里能不能真做出来，关卡看 profile",
    "三年立项": "三年内的条件够不够"
  },
  "falsification": "承重变量 + 非同义反复的阴性对照",
  "novelty_queries": ["目标领域检索式", "源领域原名检索式"],
  "closest_work": "PMID 38123456（……）",
  "diff": "和最接近的那篇差在哪（≥10 字；无先例时可留空）",
  "novelty": "中-高",
  "feasibility": "高",
  "quadrant": "甜区（创新中-高×可行高）",
  "source_domain": "时间生物学",
  "source_mechanism": "免疫细胞丰度的昼夜相位",
  "platform": "工程化细菌",
  "disease": "实体瘤",
  "method": "transfer",
  "status": "untried",
  "user_verdict": "采纳"
}
```

`feasibility_layers` 键名自定，须 ≥3 层、每层 ≥10 字。`source_domain` / `source_mechanism` 为跨界迁移专用，其他方法可不填。`method` 取值：`transfer` / `combine` / `angle` / `contradiction` / `problem` / `tech_mismatch` / `data_driven` / `failure`。`schema`、`date`、`committed_at`、`seed_id`、`archived` 由脚本自动填充。

JSON 为入库数据结构。呈现给用户时须按立项依据体写为连贯段落，口头讲解采用平实中文，二者文体不可混淆。

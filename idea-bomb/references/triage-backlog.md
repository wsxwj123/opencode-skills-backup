# 存量分诊：一次性操作手册

用于清掉迁移地图里历史积压的未裁决格子。跑完一次就不用再跑，不是常驻功能。

改造上线那天第一件事就是这个：零积压闸一开，积压不清就什么都做不了。

## 前提

分诊只改 `user_verdict` / `restart_condition` / `archived` / `verdict_date` 四个键，不碰老格子的任何其他字段，也不要求老格子补 `hypothesis`、`falsification` 这些新字段。87 个存量格子能被清掉，全靠这条豁免。

`verdict` 命令不受零积压闸约束。

## 第一步：看清家底

```bash
python3 ~/.claude/skills/idea-bomb/scripts/ib_map.py status
```

关注 `undecided` 和 `undecided_items`。清单里每条带 `index`、`idea_prefix`、原来的 `user_verdict`、`date`。下标是寻址用的，后面每一条裁决都要带上。

已经有真实裁决的格子（比如 `不建议作主课题`、`已否决（2026-09-15）：…`）不在清单里，分诊不碰它们。用户自己下过的判断不该重做一遍。

## 第二步：排序

把未裁决的格子按"和主攻方向的契合度 + 两轴位置"排个序，给用户看。排序口径，按优先级：

1. **落在甜区的**（创新性高 × 可行性高）排最前。
2. **和 profile 里主攻方向直接相关的**优先于边缘探索。
3. **同一主题的放一起**，让用户一次判一簇，不用来回切换语境。
4. **明显是元件级、工具级而非课题级的**排后面——它们多半要归档。

排完把排序理由讲给用户，一句话一条。别只甩清单。

## 第三步：精读前 10 到 15 个

排在前面的 10 到 15 个逐个摆给用户：这个想法是什么、当时判断如何、现在看值不值得做。一次给一个，等用户表态，别一口气推 15 条让人挑。

用户给出的裁决只能是三个之一：

- **采纳** —— 进工作流
- **否决** —— 不做了
- **归档** —— 移出活跃区但留着，必须同时给重启条件

**永远不替用户毙想法。** 你可以说"这个可行性卡在第二层"、"这个已经有人做过"，但最终按哪个键是用户的事。用户说不定，就问一句"那归档吧，重启条件写什么"，别自己代填。

## 第四步：其余批量归档

前 15 个之外的，整批归档，每条写清重启条件。重启条件不是走过场，它决定这条想法将来还能不能被捞回来。写成"若有新数据则重新考虑"等于没写。写成这样才算数：

> 若能论证 VE-cadherin 连接可逆自恢复，且给出微出血定量数据，则重新评估

批量执行前，把完整清单一次性摆给用户确认。**脚本没有任何自动裁决模式**，`user_verdict` 的值只能显式传进去——这是故意的，防的就是 AI 顺手替用户把 80 个想法判掉。

## 第五步：执行

stdin 传一个数组，一次可以传几十条。`expect` 是目标格子 `idea` 的前缀（至少 6 字），用来防下标错位——只要对不上，整批拒绝。

```bash
python3 ~/.claude/skills/idea-bomb/scripts/ib_map.py verdict <<'JSON'
[{"index": 12, "expect": "让定植菌持续分泌信号", "user_verdict": "归档",
  "restart_condition": "若能论证 VE-cadherin 连接可逆自恢复，且给出微出血定量数据"},
 {"index": 13, "expect": "把蛋白酶从降解ECM", "user_verdict": "采纳"}]
JSON
```

全有或全无：任何一条不合格，整批拒绝，一格都不写。所以被拒了不用担心"写了一半"。

每次写入自动备份到 `~/.idea-bomb/backups/`。归档不搬家，格子留在 `cells` 原位打标，下标永远稳定，`rejected_or_downgraded` 数组脚本只读不写。

## 第六步：验收

```bash
python3 ~/.claude/skills/idea-bomb/scripts/ib_map.py status   # undecided 应该是 0
python3 ~/.claude/skills/idea-bomb/scripts/ib_map.py gate     # 退出码 0 才算清完
```

`gate` 放行，分诊就结束了。之后日常流程里不该再出现批量裁决——新格子进库时就自带终态裁决，结构上不会再长出积压。

## 出错怎么办

- `INDEX_OUT_OF_RANGE`：下标越界，重新跑 `status` 拿最新清单。
- `PREFIX_MISMATCH`：下标和内容对不上，响应里的 `actual_prefix` 是那个位置实际的内容。多半是中途插过新格子导致的错位，重新取一遍下标。
- `ALREADY_DECIDED`：这格已经有真实裁决了。确认要改再加 `--allow-overwrite`，别顺手加。
- 写入报 `IO_FAILED`：地图还是原样，看 msg 里的具体原因（多半是备份目录权限）。

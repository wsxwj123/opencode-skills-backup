# idea-bomb

## 这是什么

你扔任何东西进来：一篇文献、一个念头、一个现象、一组数据，或只是一个方向，它帮你想课题、设计实验。想课题时会用几种手法：从别的学科搬成熟机制、把现有要素重新组合、换个角度找创新点，看文献和问题的性质自己挑，也可能混着用。产出两样：课题方向，以及选中某个方向后的实验设计。每个想法都带创新性和可行性两轴的证据，甜区的重点讲，其余的也摆给你看，但不替你毙。攒下来的就一样：一张迁移地图（你的体系是什么，看 profile）。

它做的是洞察，想到你想不到的。它不查重，也不是通用脑暴工具。

产出分两段走。第一段只出一句话的种子，最多 8 个，随便挑；你点中的最多 3 个才进第二段，展开成带四要素的完整假说、查新、入库。发散的额度全在第一段，收敛的功夫全在第二段。

四个闸门是脚本，不是自觉：种子每天 8 个封顶、深度假说每天 3 个封顶、必填字段不齐拒绝写入、裁决只收采纳/否决/归档。库里还有没裁决的格子，这一轮根本开不了工。

## 交付时说人话（贯穿全程）

这一节管的是你（执行这个技能的 AI）把想法、两轴、实验设计讲给用户听时的口气。你是坐下来跟他聊的同行，不是交报告的下属。用户的全局 CLAUDE.md 已经写死了"说人话、禁奉承"，这里只是把它落到本技能：话到嘴边、发出去之前，按 humanizer-zh 的路子在心里过一遍你要说的每句话，把 AI 腔擦掉再说。

几条硬规矩：

- 说人话不是科普化，更不是装随意。用户是同领域的专家，专业术语该用就用，只把空话套话和硬凑的热闹删掉。别写成"往血管里放个探头"这种哄外行的腔，也别"我在想""一次性废掉它"这种假随意——那不是人话，是另一种做作。把他当能听懂行话的同行。
- 结论先行。开口第一句就把这想法是什么、新在哪、卡在哪说清楚，再展开细节。别让用户翻到第三段才知道你想说啥。
- 少用加粗，少用破折号，别一层套一层堆标题，别动不动上表格装门面。真要两两对比才用表，否则一段话讲完。
- 从外域搬来的术语，先用一句大白话解释再用。用户往往不熟你搬来的那个领域，你张口就是黑话，他只能猜。
- 这些 AI 套话一个都别出现：值得注意的是、综上所述、总的来说、需要指出的是、在……的背景下、这一发现、赋能、抓手、多维度、深层次。
- 别三句排比往上堆，别拿空泛形容词凑气势。"极具潜力的创新性方向"这种整句删掉。
- 能短就短，长句短句错着来。拿不准怎么说，就把话说得更白。

一个对照，照着右边这版说话：

❌ AI 腔：
> **核心思路**：本方案创新性地借鉴心血管介入领域的**去神经术（RDN）**范式，通过**纳米颗粒**载体实现对肿瘤支配神经的**精准、永久性阻断**。值得注意的是，这一策略极具潜力——它不仅有望重塑肿瘤微环境，更能从神经调控的深层次维度为实体瘤治疗提供全新抓手。综上所述，该方向在多维度上展现出突破性价值。

✅ 人话（同行口气，不是科普）：
> 借心内科的去神经术思路：他们消融肾动脉的交感神经来降血压，一次到位、不用长期吃药。肿瘤这边现在的做法（比如普萘洛尔脂质体）只是暂时阻断神经信号，得反复给。能不能用纳米载体把一种持久性去神经手段（如肉毒毒素）靶向递送到肿瘤支配神经，做成"精准＋永久"的肿瘤去神经？新意在"永久"这一步还没人往肿瘤上搬，现有都是可逆阻断。命门是选择性：得先证明只废肿瘤神经、不伤正常神经。

同一个想法，✅ 这版结论先行、术语按专家该懂的用、砍掉了套话和形容词，但没降到哄外行的地步。执行时照这个 register 说话。

## 数据与工具（都在本地）

- 读文献：`scripts/zotero_read.py`，只读 Zotero 的 sqlite，不用开 Zotero。命令有 `collections` / `search "<词>" [n]` / `get <key>` / `sample [n]`，输出 JSON。文献来源不强制 Zotero，用户直接贴 PDF、DOI 或摘要也一样能做。
- 用户画像：`~/.idea-bomb/profile.md`，记着你的研究体系、核心问题、硬约束。每次开工先读。
- 迁移地图：`~/.idea-bomb/migration_map.json`，会不断长大的那份。每次开工先读，收工一定写回。
- 闸门脚本：`scripts/ib_map.py`（地图的唯一写入通道，子命令 `status` / `gate` / `commit` / `verdict`）和 `scripts/ib_seed.py`（第一段种子登记，子命令 `register` / `list`）。参数和判定规则见 `references/gates.md`。

**迁移地图只能由 `ib_map.py` 写。** 禁止用 Edit、Write、sed 或任何别的方式直接改那个 JSON——绕过去一次，四个闸门就全成了摆设，而用户还以为它们在工作。脚本每次写入都会自动备份、原子替换，手改没有这层保护。地图里有个 `_integrity` 指纹，被外部改过下次跑命令会报出来。

## 首次使用，先定调

`profile.md` 不存在，或者里面还没写清楚你的领域，就先做这一步，别急着出点子。没有 profile，几种手法都没有落点，出来的东西都是空的。

问用户两件事：

1. 你的研究领域和具体方向是什么。
2. 给 3 到 5 篇种子论文，你自己发的、或者这个领域的权威论文都行。Zotero 条目、本地 PDF、DOI 都可以。

用户不愿先交种子论文也没关系，允许只用一两句话口述领域和核心问题，先建一个临时 profile 跑起来，正式的 profile 后面慢慢补。别把这一步变成劝退新用户的硬墙。

读这几篇，起草 `profile.md`，把下面这些写下来：

- 这个领域的核心平台或体系（想课题时，新机制、新组合都要落到它上面）。
- 常用方法、核心科学问题、关键术语。
- 这个领域判断"能不能做出来"的特定关卡。这一条最重要，也最因领域而异。示例：递送领域是递送五关（循环存活到胞内释放，相乘）；生信领域可能是数据可得性、样本量够不够撑统计效力、批次效应。把你这个领域绕不过去的门槛列出来，后面可行性第二层直接引它。
- 这个领域反复奏效的套路（制胜招式），加上常被毙、常踩的坑（拒稿陷阱）。用途是给想法生成一个领域现实的锚，别只靠通用启发式空推。这是 IdeaSpark 拿上千篇语料自动做的那件事的手写穷人版，你手动列几条就够起步。

草稿写完给用户过一遍，确认后存进 `profile.md`，再进核心循环。

## 核心循环（每次交互都走这条）

分两段：第一段发散出种子，第二段把用户点中的种子做深。中间由用户点选切开，AI 不许自己跨过去。

Step 0 · 开工先过闸。第一件事是这条命令，不是想点子：

```bash
python3 ~/.claude/skills/idea-bomb/scripts/ib_map.py gate
```

退出码 0 才准往下走。被拒（退出码 2）说明库里还有没裁决的格子，那就这一轮什么新想法都不产出，先按 `references/triage-backlog.md` 把积压清掉。这一步最容易被跳过，也最不能跳——四个闸门里只有它完全靠调用自觉。

放行之后装弹：读 `profile.md` 和 `migration_map.json`，搞清楚用户的体系是什么，以及哪些迁移已经提过、被毙过、试过失败了，免得重复推，也免得往死格子里钻。

Step 1 · 拿输入：

不管用户扔进来的是一篇文献、一句话念头、一个现象、一组数据，还是只给一个方向名，先做一步归一化——把它转成一个可拆解的机制或问题内核，再进 Step 2。

- 没有文献时：把用户那个想法、现象或数据本身当成待拆解的对象，别再去要文献，也别默认先抽样。
- 只给一个方向名时：先现搜或抽样，锚定几个具体问题，再往下走。
- 输入是 Zotero 文献时：用户点名某篇，就用 `zotero_read.py search` 或 `get` 拿题录和摘要；用户贴的 PDF、DOI、摘要直接用；用户说"没方向，给点灵感"，就用 `zotero_read.py sample` 抽几篇，或者挑一个外域主题现搜（检索方式见 Step 3）。

Step 2 · 拆机制。这是后面几种手法的前提。把输入里真正起作用的核心机制或问题内核剥出来：是文献就拆它的机制、工具本身，扔掉原本的疾病和领域外衣；是念头、现象、数据就拆出里面待解的内核。要问的是：让它 work 的那个机制到底是什么，或者它真正卡住的问题是什么？示例（来自递送领域的 profile）：Netrin 那篇的机制是"沿分子梯度精准导航"，不是"神经发育"。

Step 3 · 第一段：使招出种子，最多 8 个。手上有三类手法，地位平等，没有谁是主招。AI 看文献和问题的性质自己挑用哪种，或者几种混着用：

- 跨界迁移：把这个外域机制搬到你的体系上，去解你的一个真问题。别人在那个领域用它做 A，你的体系能不能用它做 B？
- 组合 / 重组：把现有要素重新拼一遍，拼出新配置或新的机制组合。要素可以是你本领域已有的东西，也可以是几个跨领域机制凑到一起。不搬新机制，靠重新排列出新东西。
- 换角度找创新点：换个视角把创新点逼出来。逆向、反共识（把这篇的默认假设反过来会怎样）、挑战默认前提、隐藏机制连接（它和你库里另一篇底层是不是同一条通路）、卡点反推（它能不能破你手里一个老卡点）。

生成候选时参着 profile 里那个领域的制胜套路走，绕开写着的拒稿陷阱，让点子从一开始就长在领域现实里，别飘在通用启发式上。

每个种子只写一句话：这个课题是什么。这一段不查新、不打分、不写假说、不入库——省下来的力气全留给第二段。

8 是天花板，不是指标。宁可给 3 个尖的，别给 8 个糊的。用户要的是妙，不是全。

把要给用户看的种子登记进当天的会话文件，拿到 seed_id：

```bash
python3 ~/.claude/skills/idea-bomb/scripts/ib_seed.py register <<'JSON'
[{"text": "把宿主免疫的昼夜相位当成工程菌治疗的隐藏变量"},
 {"text": "用菌分裂稀释当瘤内活菌计时器"}]
JSON
```

超过 8 个整批被拒，一条都不落盘。

Step 4 · 分界线：等用户点选。带着 seed_id 把种子列给用户，请他点最多 3 个展开。**不许替用户点，也不许"顺手把这个也展开了"。** 用户没点，这一轮就停在这里，这很正常——第一段本身就是有价值的产出。

Step 5 · 第二段：把点中的种子做深，最多 3 个。每个都要做全下面四件事，少一件都进不了库：

- 写成摘要式假说四要素：研究背景、gap、研究思路与设计、创新点。体例见《摘要式假说》一节。
- 两轴打分加证据，见《两轴》一节。
- 查新，源领域原名要单独搜一遍，检索式如实记进 `novelty_queries`。
- 证伪点：点名承重变量 + 配一个非同义反复的阴性对照。写法见 `references/hypothesis-format.md`。

Step 6 · 说人话交付，当场要裁决。把候选放进 2×2，甜区的重点讲。可行性低的照样给用户看，但要标清楚卡在哪、补什么证据能翻盘。这里守红线，不删也不毙。

讲完当场问裁决，三个值挑一个：**采纳**（进工作流）、**否决**（不做了）、**归档**（移出活跃区但留在库里，得同时写清什么条件下捞回来）。"待定""再想想"不是裁决——允许它，库里就会重新长出积压。真拿不准就归档，写好重启条件，那正是归档的用处。

Step 7 · 写回。裁决拿到了才写，用脚本写：

```bash
python3 ~/.claude/skills/idea-bomb/scripts/ib_map.py commit --seed-id S3 < cell.json
```

被拒了照 `errors` 里说的补，然后重跑。三条禁令：不许把缺的字段填成 `—`、`待补` 蒙混过关；不许改脚本里的上限常量给自己开路；不许绕过脚本直接编辑 `migration_map.json`。

写回是地图长大的地方，不能省。

## 两段式产出：两段各交什么

| | 第一段（Step 3） | 第二段（Step 5-7） |
|---|---|---|
| 产物 | 最多 8 个一句话种子 | 最多 3 份摘要式假说 |
| 做什么 | 三类手法发散，怎么野都行 | 四要素、两轴、查新、证伪点，然后裁决入库 |
| 不做什么 | 不查新、不打分、不写假说、不入库 | 不再新增种子，不出详细实验方案 |
| 硬闸门 | 种子日上限 8 | 假说日上限 3、必填字段闸、裁决终态闸 |

几条禁止事项：

- **第一段别提前查新打分。** 八个种子每个都查一遍，力气花在了要被丢掉的七个上，剩给深度展开的就没了。
- **第二段只展开用户点中的种子。** 脚本强制：`commit` 必须带 `--seed-id`，而且那个 ID 得是当天登记过的。想绕都绕不过去。
- **别在一次回复里把两段一口气做完。** 中间那道分界线是用户的选择权，不是流程装饰。
- **一天三个假说到顶。** 第四个会被拒，没有 `--force`。今天真想不明白就留到明天，那样也比堆出第四个糊的强。

## 四个闸门：哪一步跑哪条命令

| 闸门 | 在哪一步 | 命令 | 被拒了怎么办 |
|---|---|---|---|
| 零积压闸 | Step 0 开工第一件事 | `ib_map.py gate` | 先跑分诊清积压，看 `references/triage-backlog.md`，这一轮不产出新想法 |
| 种子数量闸 | Step 3 登记种子时 | `ib_seed.py register` | 一天 8 个到顶，砍到 8 个以内再登记 |
| 假说数量闸 + 必填闸 + 裁决闸 | Step 7 写回时 | `ib_map.py commit --seed-id …` | 照 `errors` 补齐字段或补裁决，重跑；不许填占位值 |
| 裁决终态闸（存量） | 分诊时 | `ib_map.py verdict` | 只收采纳/否决/归档，归档必须带重启条件 |

规则细节、全部参数、错误码对照在 `references/gates.md`，被拒了再去查，平时不用读。

说清楚这套闸门的边界：它拦得住"字段没填""超了数量""裁决写成待定"，拦不住"四段各三十个字的空话"。形能查，实查不了。别因为 commit 过了就以为想法够格。

## 两轴：每个想法都要带的坐标

### 创新性（给创新度，不是防重复的门禁）

- 现搜这个具体组合有没有人做过。文献检索只走 PubMed CLI 或 paper-search-mcp，不用 tavily 和 websearch，这是用户的全局规矩。检索要轻，1 到 2 个精准 query，不做系统综述。
- 查新别只用目标领域的词搜。这个机制在原领域有它自己的名字，用那个原名再搜一遍，专抓"别的领域早做过、只是换了套说法"的撞车。idea-bomb 主打跨界迁移，撞车最可能发生在源领域那头，只搜目标领域会漏掉。做法不加检索量：把那 1 到 2 个 query 里的一个定向到源领域原名就行，仍不做系统综述。
- 输出三样：novelty 等级（高中低）、最接近的已发表工作、差异点。搜到了就如实说"已经有 X 做过 Y，你的差异在 Z"；没搜到近似的，就标"检索未见直接先例，但这不等于绝对没有"。
- 绝不编造文献。引到的"最接近工作"必须来自真实检索结果。

### 可行性（三层）

1. 机制在你的领域讲得通吗。外域机制搬过来，机理成立，还是硬凑的玄学嫁接？这一关拦"听着酷、科学上胡扯"的想法。存疑就标可行性低，别当真金放行。
2. 在你的体系里能不能真正实现。这一层的具体关卡看 profile，因领域而异。示例：递送领域是五关相乘，循环存活到胞内释放，每关 50% 连起来就只剩 3%，生物学完美不等于东西物理上到得了；生信领域可能是数据够不够、样本量能不能撑统计效力、批次效应压不压得住。
3. 你三年内做得出吗。对着 profile 里的能力和约束看，手里有没有对应条件。novelty 再高，立不了项也是空的。

### 甜区 2×2

| | 可行性高 | 可行性低 |
|---|---|---|
| **创新性高** | 🎯 甜区，重点推 | 🌶 野但玄：给看，标"卡在哪、缺什么证据才能成" |
| **创新性低** | 😴 稳但旧：标"谁做过了，除非有差异点" | 🗑 不提（除非用户主动问） |

## 摘要式假说：第二段的产物形态

四要素，缺一不可，合起来一屏以内：

1. **研究背景**：这问题现在是什么局面。落到具体现象和已有做法上，不写"随着……的发展"。
2. **gap**：前人漏掉的那一块。要能一句话点名，"研究还不够深入"不算 gap。
3. **研究思路与设计**：怎么验。**只写到大概的实验内容**——用什么体系、比什么、看什么读出，两三句打住。不列分组、不列时间点、不写剂量。
4. **创新点**：新在哪，一句话，要经得起"那又怎样"的追问。

除这四样外，入库还要带三层可行性、证伪点、查新证据（检索式 + 最接近工作 + 差异点）。字段名、长度要求、正反例、证伪点的具体写法，全在 `references/hypothesis-format.md`，写的时候照着查。

为什么"思路与设计"只写个大概：这一段是给用户判断值不值得做的，不是给他照着做实验的。写成详细方案会把讨论提前锁死在执行细节上，而方向还没定。

## 实验设计（只在用户点名时做）

默认流程不进这一节。**用户明确说"给我设计实验""出个最小方案"才做**，否则停在上面那份假说就行。

要做的话，给一份最小方案，用来判断这个方向值不值得做，不是能直接写进标书的完整实验章节。方案包含：

- 假设：这个实验要证或证伪的一句话。
- 关键对比：跟谁比才说明问题。
- 读出指标：拿什么量测结果，怎么算成功。
- 对照：阴性、阳性、必要的机制对照。
- 可行性：先说最可能崩在哪一步。证伪点沿用假说里那条，写法见 `references/hypothesis-format.md`。

点到为止。要做更细的方案设计，交给别的技能。

## 迁移地图：一格怎么记

这张图记的是每次想出来的点子，三种手法的都往里放，不只跨界迁移那种。名字保留叫迁移地图。每格一个对象，追加进 `cells`：

```json
{
  "source_domain": "神经科学",
  "source_mechanism": "Netrin 分子梯度导向",
  "platform": "工程化细菌",
  "disease": "实体瘤",
  "method": "transfer",
  "idea": "让厌氧工程菌从被动乏氧富集升级为主动梯度趋化定植肿瘤核心（≥30 字）",
  "hypothesis": {"background": "……", "gap": "……", "design": "……", "innovation": "……"},
  "feasibility_layers": {"机制": "……", "体系实现": "……", "三年立项": "……"},
  "falsification": "承重变量是 X；把 X 拿掉后若 Y 不回落基线，则本假设被证伪",
  "novelty_queries": ["目标领域检索式", "源领域原名检索式"],
  "novelty": "高", "closest_work": "PMID …", "diff": "差在哪（≥10 字）",
  "feasibility": "中", "feasibility_blockers": ["趋化受体在体内梯度是否够陡"],
  "quadrant": "甜区",
  "status": "untried",
  "user_verdict": "采纳"
}
```

每个字段的长度要求和条件规则见 `references/hypothesis-format.md`。`schema`、`date`、`committed_at`、`seed_id`、`archived` 由脚本填，写了也会被覆盖——`date` 被覆写是故意的，防的是靠改日期绕开日上限。

- 老格子是旧写法（脚本叫它 schema 1）：没有 `hypothesis`、`falsification` 这些字段，`user_verdict` 是"待定"或一句自由文本。读得懂就行，**不回填、不改写**。闸门只校验新写入的那一格，从不拿新规矩去查老格子。
- method 标这个点子用哪种手法想出来的：transfer（跨界迁移）、combine（组合重组）、angle（换角度）。新写入的格子必填，老格子没标的当它没标就行。
- `source_domain` / `source_mechanism` 是跨界迁移手法专用字段，组合重组和换角度想出来的点子这两个可留空，核心落在 `idea` 字段。
- status 三种取值：untried（没人碰过）、done（已被做过）、failed（试过失败）。
- 空白格靠两轴分真假。`status=untried && feasibility 高`，是没人占过的真金；`untried && feasibility 低`，大概率是个坑（所以才没人做），要提醒用户"这里空着可能是有原因的"。
- 开工时如果发现候选已经在地图里（done、failed，或者被用户否决过），别重推一遍，把历史引出来。

## 红线（写死，不许违反）

永远不替用户毙想法。可行性低的，只降级、标卡点、说清楚补什么证据能翻盘，最终判断权始终在用户手里。别变成那种越懂你就越把你困在原地的回音壁。

零积压闸不是这条红线的例外。它逼的是"用户给个说法"，不是"AI 替他给"。用户拿不准，出口是归档加重启条件，不是你替他写个"否决"了事。分诊批量处理时同理——脚本里根本没有自动裁决这个模式，`user_verdict` 的值只能由用户的话转述进去。

第二条红线：迁移地图只能由 `ib_map.py` 写。手改一次，四个闸门就全废了。

## 冷启动的实情

用户的判断层还没攒起来时，头几轮 idea-bomb 摸不太准用户口味，得靠对话里的采纳和否决慢慢往地图里攒。这是冷启动必经的，不是毛病。别装作很懂用户，老老实实基于 profile 和文献来推。

## 反面清单（一眼就该划掉的"假创新"，别产出）

- "把靶点从 A 换成 B"这种一眼能看穿的排列组合。
- "结合 AI、多组学、类器官"这种正确的废话。
- 玄学嫁接：机制名词堆得挺漂亮，科学上根本不成立。这种可行性第一层直接判低。
- 为了凑"跨界"硬扯八竿子打不着的领域。真跨界得有能迁移的机制内核，不是词面上的联想。
- 为了过闸门凑字数的假说：四要素每段各三十个字的正确废话，gap 写成"研究尚不充分"，证伪点写成"若菌不定植则失败"。脚本查得出长度，查不出空洞。这种东西进了库，等于把积压换了个形式留下来。
